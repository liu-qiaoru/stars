# 检索 Agent 第一版

Stars 默认多轮检索先由程序使用完整用户原文搜索，新图文协议直接准备搜索实际命中的图片与文字，在同一次DeepSeek请求中判断证据并选择“必要详情、有理由补搜或完成”；未启用新协议的旧部署仍准备限长概要。例如“小猫趴在猫爬架上”的描述只有“小猫”和“猫爬架”，仍不能确认“趴在上面”。可以继续读取其他候选，或针对该缺口补搜；不强制增加轮次。增强通过逐查询人工质量验收前，正式结果始终使用原文基线。

2026-10-07停止规则修正：命中模式采用`matched-pixel-stop-v2`决策策略，素材传输仍是原`matched-multimodal-v1`许可范围，图片数量/分辨率和费用门不扩大。视觉条件只有Caption或转录引用时程序保留unknown并记录`visual_requires_pixel_evidence`；有效像素引用只证明来源存在，仍不证明模型看对。模型若有忠实且不同的缺口查询应补搜，必要详情必须能提供新信息；不能为体现多轮强制补搜。

命中模式的模型finish必须提交有界`stop_basis`，保存原条件身份、最多3个已提供候选的引用，以及补搜/详情为何不再有用。`sufficient_evidence`只能用于完整支持候选，`no_results`只能用于实际搜索后空候选；partial等使用`no_useful_next_action`，包含已承认的未知条件和两种行动各自的理由。程序验证身份、来源及实际预算，不能把“模型说没有用”当作语义真值。缺失或伪造依据进入原有限纠正，仍失败则明确证据不足保底；不增加纠正、模型或工具上限。页面展示这些停止意见及原条件。

新策略写入任务配置和质量摘要。旧任务尚未完成规划且策略不同则停止增强、保留已提交基线；已冻结的最终名单和独立重排授权恢复继续原交接，不重新请求决策或换名单。旧真实报告保留但不授予新策略质量资格。无需数据库迁移、回填或重新索引；本轮只有本地测试，真实自主补搜和新策略质量未验收。

这是已有 NestJS 服务端执行器的扩展，没有引入新 Agent 框架。Python Worker（后台处理程序）继续负责原有索引任务；此次没有改模型权重、数据库产品或普通搜索算法。

## 使用与启动

1. 按 README 启动 PostgreSQL（保存文件、任务与步骤事实）、Qdrant（保存检索向量）、本地模型服务、服务端和 Web。已有可检索素材不必重新扫描。需要新素材索引时才需运行 Python Worker；Caption 尚未生成不会由本功能自动补生成。
2. 由部署者保留现有 `RIGHT_CODE_BASE_URL` / `RIGHT_CODE_API_KEY`，配置 `ALLOW_EXTERNAL_LLM=true`、`AGENT_EXECUTOR_ENABLED=true` 后启动或重启服务端。这些外部开关在示例配置中仍默认 false。不要把密钥写进请求、截图或日志。
3. 启动命令仍是 `corepack pnpm dev` 和独立的 `corepack pnpm dev:model`；数据库容器启动方法见 README。打开 `/agent`。
4. 默认使用多轮检索。提交时授权发送用户输入；“允许发送素材文字用于多轮判断”需要另行勾选。它覆盖候选标识、媒体信息、有限画面描述与转录，不包含图片和本地路径。不勾选时视觉任务先完成本地原文基线搜索，再在素材文字外发前暂停，页面可补充回答并授权后继续。
5. 页面展示实际搜索次数、查询、候选预览、逐条件判断、证据与结束原因。运行中可取消；问题可在原任务内回答。页面刷新后继续读取同一任务，不重新发起模型请求。
6. 多轮检索也会在检索结束后进入最终图片重排。部署需配置 `AGENT_RERANK_PROVIDER=dashscope` 与百炼凭证，用户需独立勾选“允许智能重排”。没有图片授权时保存选中候选并等待授权，恢复后不会再次调用决策模型。视频重排需要 Python Worker 生成派生拼图。导出仍须选择“检索与导出”；多轮检索本身不创建导出。

手动验证会产生 RightAPI 费用，并可能发送勾选范围内的素材文字。真实验证记录按日期单独保存，不把自动化通过、任务成功或到达最终重排当作质量通过。当前验收材料见仓库 `.scratch/retrieval-quality/`。

## 调用顺序与职责

1. `AgentService.createRun` 校验输入，将原始目标、硬范围、逐项授权写入现有 PostgreSQL 表，立即返回任务 ID。Web 不等待搜索完成。
2. `AgentExecutorService` 领取带版本号的租约（限时执行权），为一次步骤分配独立身份。模型调用前先保存 `dispatched`，再离开数据库事务进行网络请求。
3. 现有 `QwenAgentIntentRunner` 保留类名以减少接线改动，但默认模型为 **glm-5.3**；示例配置显式启用 `AGENT_RETRIEVAL_EVIDENCE_MODE=matched_multimodal` 和 `AGENT_RETRIEVAL_MODEL=deepseek-v4-flash`，意图与图文决策仅使用DeepSeek。没有新模式配置的旧部署继续overview和原默认GLM；单独设置DeepSeek模型的旧模式仍可用于历史任务。新模式显式选择GLM会在启动时报错；历史任务恢复时模式或模型改变则停止并保留基线，不会因失败自动换回GLM。它提取必须条件、排除条件和检索范围；条件原文必须来自用户输入，条件 ID 由程序生成。多轮流程另保留完整用户原文条件，防止拆分条件时遗漏动作与关系；这只能保住原始目标，不能证明模型拆分语义正确。
4. `RetrievalAgentHandler` 先同步等待原文基线搜索：同一已解析范围、`original` 查询模式、RRF 排序、最多20条。`original` 表示不调用 DeepSeek 扩展，不能理解成允许 GLM 改写原文。仅纯转录词语检索保留原有关键词边界。原文上限为4000个 Unicode 字符（包括可能占两个编码单元的字符）。再由 `RightApiRetrievalDecisionRunner` 请求一个结构化动作。程序用共享的数据约束（Schema，规定允许字段与类型）验证动作。模型可以读取详情、有理由补搜、澄清或完成任务。
5. 工具动作先持久化为 `pending`。下一步骤才执行工具并保存原始工具返回值、更新工作状态、合并候选。每次搜索仍调用原有 `SearchService`。
6. 完成时程序重新读取候选与证据，对比版本和内容指纹。只有真实候选及属于该候选的证据可以被引用。只有本轮已发送的命中证据或详情可以支撑有引用的判断；未提供证据的候选保持无引用的 unknown（无法确认）。无效判断保存被拒绝的动作、Provider 信息和具体校验原因，允许有限纠正，不再一条错误判断就终止整个任务。
7. 有效视觉候选进入 `ranking`（等待最终重排），并在同一数据库事务中创建重排尝试。正式名单保存为 `rerank_candidate_keys`，最多20条；质量未验收时名单是冻结基线。所有搜索候选和逐轮名次保留供审计。不能凭描述缺失或模型文字判断删除基线；已删除或旧索引候选按身份有效性剔除，并明确记录失效。
8. `AgentRerankService` 为选中视频创建后台图片任务，Python Worker 生成拼图并写入本地证据记录；图片候选直接使用当前图片。服务端等待证据完成，核对授权、任务状态、文件/场景版本和图片指纹后，同步等待百炼 `qwen3-vl-rerank` 的排序响应。请求只发送完整原查询和派生图片，不发送候选 Key、路径、Caption 或转录。成功按重排顺序返回。失败、超时或未知外发时可展示已提交的基线检索顺序，但必须显示 `final_rerank_status=not_completed` 和保底原因，不能冒充最终重排；取消任务不展示新结果。保底不会重复未知请求。
9. 纯音频和没有场景身份的转录结果没有可用于图片模型的场景画面，保留只读文本结果并标记重排不适用。用户看到模型判断与原始证据，而不是内部思考过程。

`search_media` 固定 `query_expansion_mode=original`，因此不会触发额外查询扩展模型；固定 `ranking_mode=rrf`。RRF（倒数排名融合）只按各检索通道中的名次组合结果，分数不是满足用户条件的概率。视频按文件/场景身份去重，图片按同文件当前版本关联已有身份；重复命中保留每轮实际查询、原始名次与来源，不覆盖基线。逐轮 `ranks[].hits` 保存折叠前每份素材的身份、名次和通道，场景代表名次使用该轮最早命中的原始名次，不能改成去重后的列表位置。模型没有 `library_ids` 参数，实际素材库过滤始终由程序从任务硬范围填入。

详情或补搜动作的 `gap` 必须引用本任务原始 `condition_ids`，列出 `checked` 候选及证据身份，说明缺什么与为什么行动，并声明原目标仍约束结果。`kind` 分别表示无候选、未读详情、描述未提及、相反证据、失效或实际工具失败。只核对未读候选身份时允许空证据列表，程序写 `read_status=not_read`；不允许伪造证据。已有多个候选时，补搜前至少检查两个（只有一个则检查它）；这只是避免未经检查默认补搜的执行规则，不是语义正确性的证明。重复查询忽略空白、大小写和 limit 变化，有限预算耗尽即停止。缺少描述必须保持 unknown；不符合判断需 `basis=explicit_contradiction` 及真实引用，仍只是模型意见。

实验选择由 `retrieval-candidates.policy.ts` 负责：20个席位最多预留4个给新增候选，其他优先基线；根据各轮 `1/(60+名次)` 累加，稳定身份破同分，空位再补齐。只比较名次，不比较不同查询或重排批次的原始分数。该名单保存在 `experimental_candidate_keys`，正式流程不额外发送实验重排；在隔离验收中可使用单独授权比较它，任何逐查询退化或缺失标签均不能推广。

`get_segment_details` 只接受当前任务中的 `candidate_key`，不接受路径或模型自造时间。它校验文件删除状态、磁盘大小和修改时间、素材库、候选 asset、场景 generation（索引版本）及活跃向量引用。视频转录命中可能没有场景 ID，此时保留转录自己的真实片段范围，并读取重叠场景的当前描述。

## 证据与信息边界

- Caption 标为 `pre_generated_caption`：它是预先生成的画面描述，不是本轮观察视频的结果。
- 转录保留真实起止秒数；超出当前片段时标记 `crosses_scene_boundary=true`，不把整段话伪装为完全发生在场景内。
- 完成后文件仍可能变化；页面读取前再次检查，失效候选移出预览并标记历史判断。
- 每次最多返回 8 条文字证据，每条最多 1200 个 JavaScript 字符，另加媒体信息证据；多出行或文字时返回 `truncated=true`。原始文字仍可通过 asset ID 与内容指纹追溯到本地记录。
- `available` 表示有当前有效文字；`empty` 表示查到了记录但没有正文；`missing` 表示没有相关记录；`stale` 表示文件、场景、索引或描述版本过期；`read_failed` 表示实际读取失败。未找到候选、没有文字和调用错误是不同情况。
- 字幕、描述和所有第三方素材文字在模型指令中均标为不可信数据；它们不能更改工具权限、外发授权或任务范围。
- 对模型实际选择评估的候选，必须给出所有原始条件的 `satisfied / not_satisfied / unknown` 判断。非 unknown 判断必须引用真实证据；程序对明确包含“连续、持续、不间断”等要求保守降为 unknown，且所有详情固定声明 `continuous_action_verified=false`。
- **引用真实不等于语义正确。** 连续动作识别、隐含条件是否完整提取、证据是否真正支持判断仍需真实查询评测和人工核验。可选场景工具仅检查采样画面，没有播放视频或验证连续动作的能力。

## 保存、恢复与限制

本次复用现有 JSON 字段，不新增数据库迁移，不修改真实素材或重建索引。

| 保存位置 | 内容 |
| --- | --- |
| `agent_runs` | 原始目标、不可放宽的素材范围、状态、租约、等待期限 |
| `agent_run_steps.output_json` | 每轮动作、工具原始返回值、工作状态、查询历史、详情和最终条件判断 |
| `agent_run_candidates` | 同一任务内去重候选；重复搜索保留各轮查询来源和原始结果 |
| `agent_run_inputs` | 用户补充文本、独立授权选择、取消与未知结果重试输入 |
| `agent_run_authorizations` | 当前任务的输入、素材文字和图片授权，彼此不能替代 |

给模型的上下文最多含 20 个候选及各自概要、最近 3 份详情及最多 4 次澄清回答；省略数量显式标记。超过澄清上限会停止，而不是删掉用户回答继续执行。用实际请求体预检100000 UTF-8字节上限；必要时省略最旧的完整详情并更新可引用名单，原文、条件、可见候选及概要保持完整。仍超限则停止增强、保留基线，不派发决策。所有工具原始返回值仍在步骤表，可用于回放与审计。

| 配置 | 默认及含义 |
| --- | --- |
| `AGENT_MAX_STEPS` | 4；单任务搜索与逐候选详情读取的总操作上限（批量按候选数计），合法范围 1～10 |
| `AGENT_TOOL_TIMEOUT_MS` | 10000 毫秒，即 10 秒；本地搜索/详情工具的单次上限 |
| `AGENT_MODEL_TIMEOUT_MS` | 60000 毫秒，即 60 秒；外部意图识别/决策模型的单次等待上限，与工具时限分开 |
| `AGENT_RETRIEVAL_TIMEOUT_MS` | 600000 毫秒；从任务创建算起的总时限，包含排队和等待用户时间，合法范围 1000～3600000 |
| `AGENT_RETRIEVAL_MAX_NO_PROGRESS` | 2；连续无新增候选或无新正文证据的次数（媒体身份与尺寸不算正文），合法范围 1～5 |
| `AGENT_RETRIEVAL_MAX_RETRIES` | 1；明确失败的额外尝试次数，合法范围 0～2 |

模型请求和外层执行器同时读取独立模型时限，本地工具继续读取工具时限，避免模型尚在等待就被 10 秒工具上限提前结束。两者仍受活动步骤上限和整任务剩余时间约束。设置页“模型等待超时”对应 `model_timeout_ms`，保存后下一次意图/决策调用立即生效；进程重启恢复环境变量值。租约（限时执行权）必须覆盖活动、工具、模型三个时限中的最大值并额外留 5 秒提交结果，否则刚收到的响应可能因执行权过期而被丢弃。超时结果仍标为未知，不自动重放。

决策调用独立限制为 `AGENT_RETRIEVAL_MAX_MODEL_CALLS` 次，默认8次，按已派发步骤统计，失败和结果未知的请求也占额度；总领取次数还有 `(冻结工具总额 + 冻结决策总额) × 4 + 8` 的兜底上限。搜索或详情重复调用会停止。总时限到达后即使用户补充回答，也只会保存 `time_limit`，不会继续外发；需要继续时创建新任务。

可确定的协议失败、明确限流和本地工具失败按上述有限额度处理。网络中断、服务端 5xx 或模型硬超时可能已经产生费用，进入 `outcome_unknown`，不自动重发、不切换模型。取消后的结果和旧租约结果无法覆盖新状态。原有 `/retry-unknown` 仍要求用户显式操作。

### 决策调用的排错记录

服务端日志默认输出到启动终端。决策错误即使被检索处理器接住、准备再次尝试，也会输出 `retrieval_decision_failed` 告警，包含任务编号 `run_id`、步骤编号 `step_attempt_id`、执行权版本 `lease_version`、请求指纹 `input_fingerprint`（请求内容的摘要，不包含正文）、累计失败次数和是否准备重试。未被内层接住的错误由执行器打印错误日志。日志中的身份字段可以关联到同一条数据库步骤记录。

HTTP Runner（负责发出一次模型请求并解析响应的程序）为失败生成 `diagnostics` 安全摘要，随步骤保存到现有 `agent_run_steps.output_json`。内层重试与终态失败均保存；网络中断、5xx 等未知结果也保存已有摘要，但仍不自动重发。写入和步骤状态在同一事务中完成，并沿用执行权检查，旧执行器不能覆盖新步骤。不需要新增数据库迁移、回填或重新索引；历史错误没有记录的细节不能补还原。

通过只读 `GET /agent/audit/runs/:id` 查看 `agent_behavior.steps[].output.diagnostics`；审计页 `/agent/audit` 的“Agent 行为与 Rerank 尝试”也展示该字段。查看记录不会调用模型。终端关闭后仍可以读取数据库记录，无需依赖终端滚屏。

摘要区分 `response_json`（响应整体不是合法 JSON，即机器可读的字段结构）、`response_protocol`（结束原因、工具数量、参数 JSON 或 decision 包装不合法）、`model_identity`（模型或工具身份不符）、`action_schema`（动作的字段类型、必填项或范围不符）。请求大小、网络、HTTP 状态及响应读取失败也有独立阶段。`reason` 为固定错误分类；`issues[].path` 是字段位置，例如 `assessments[0].conditions[1].condition_id`，不包含字段值。错误位置最多保存 20 条，多出的数量记为 `omitted_issue_count`。

摘要还包含 Provider 请求编号（优先响应 ID，缺失时使用约定的请求编号响应头）、HTTP 状态、模型结束原因、工具调用数量、已报告的输入/输出 token 用量（模型计量的文本单位，不能直接当作字符数或费用）、输出上限、推理档位、超时设置、上下文中的候选/详情/查询数量、请求/响应字节数以及耗时。字节数使用 UTF-8 编码长度；时间单位均为毫秒。缺失用量和无法取得的数据保持 null，不按 0 处理。

仅保存固定分类、允许字段位置和限长编号，不保存原始请求/响应、错误字段值、API Key、本地路径、Caption、转录或模型思考。未知元数据归为 `unexpected`/`other`，不复制它的原文。诊断补充不放宽动作校验、不改变已有重试次数，也不会替代人工检索质量核验。

`stop_reason` 区分 found、partial、no_results、insufficient_evidence、conditions_not_met、no_progress、repeated_call、tool_limit、model_limit、step_limit、time_limit、tool_timeout、tool_failed、model_failed、clarification_limit。新视觉任务的 `succeeded` 表示最终重排成功（没有可用候选时为空结果结束），**不保证找到满足全部条件的素材**；应同时查看结束原因和逐条件判断。

## 候选概要与小批量详情（2026-10-06）
