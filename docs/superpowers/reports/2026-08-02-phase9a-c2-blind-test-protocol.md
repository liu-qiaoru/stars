# Phase 9A-C2：未见样本与标签一致性复测协议

## 结论与边界

本轮新增 30 条“查询—视频场景”样本，用来区分两类问题：模型判断错误，以及人工参考
标签本身存在歧义。样本从 Phase 8 已冻结且已经索引的素材中只读选择，因此不需要数据库
迁移、数据回填或重新索引。

人工参考标签冻结前，不调用本地或云端 VLM（Vision-Language Model，视觉语言模型，即
同时读取画面和文字问题的模型）。原 Phase 9A 的 12 条已被模型反复观察，只作为将来的
回归对照，不计入本轮 30 条主要质量指标，避免 Prompt 只适应旧题。

## 样本冻结规则

选择器必须满足以下规则，否则立即报错，不生成缩水或部分样本：

1. 固定读取 Phase 8 正式 run `6298b745-d9d3-44bf-86a0-2d0a0b46360c`。
2. 精确选择 30 个不同的查询—视频场景组合，并排除原 Phase 9A 的 12 个组合。
3. 覆盖 10 条动作/状态、10 条人物—物体/空间/环境关系，以及 10 条明确对照样本；
   明确对照样本按 Phase 8 旧标签分层选择 5 条高度相关和 5 条不相关，但旧标签不写入
   盲标包。
4. 至少 8 条只由 Caption 通道召回，至少 16 条由 SigLIP2 视觉通道召回。Caption 是模型
   生成的画面文字描述；SigLIP2 是把查询和画面变成向量后按相似度召回的视觉模型。
5. 同时覆盖短场景和接近 30 秒的场景，避免只测试容易抽帧的短片段。
6. 盲标包只能包含稳定 UUID、查询、必须条件、排除条件、媒体类型和场景起止秒数；不得
   包含旧人工等级、检索来源分数、current/RRF 名次、Caption 原文或本地绝对路径。
7. 样本选择使用固定算法和固定种子；同一数据库快照重复运行必须得到同一清单。

上述 0/1/2 配额只用于按 Phase 8 旧标签分层抽样，不是本轮答案配额。盲标包不会披露旧
等级的逐题映射或汇总数量，A/B 标注者也绝不能为了凑数量修改判断；新标签分布可以与旧
标签不同，这正是本轮要测量的现象。

“确定性”表示相同输入一定得到相同输出。这里使用它是为了防止看到模型结果后偷偷换题。

## 人工标注规则

每个必须条件和排除条件都分别选择：

- `是`：画面能够直接支持该条件；
- `否`：画面能够直接否定该条件；
- `不确定`：抽取画面不足以支持或否定，不能靠常识补全未显示的事件。

系统按固定规则推导整体等级，人工不直接输入 0/1/2：

1. 任一条件为“不确定”时，整条记为 `unjudgeable`（无法可靠判断），不强迫猜测。
2. 任一排除条件为“是”时，相关等级为 0。
3. 所有必须条件均为“是”且所有排除条件均为“否”时，相关等级为 2。
4. 只有部分必须条件为“是”、其余为“否”，且没有命中排除条件时，相关等级为 1。
5. 所有必须条件均为“否”时，相关等级为 0。

例如查询“有人用筷子吃盒饭”拆成“有人”“有筷子”“有盒饭”“正在夹取或进食”。画面
只有人拿筷子、没有盒饭时会自动得到 1；画面能看到全部四项且没有排除项时得到 2；只能
看到静止人物、无法确认进食动作时应把动作标成“不确定”，而不是猜测 1 或 2。

## 双人或复标一致性

优先由两个人独立标注，双方都看不到旧标签、模型输出和对方答案。若暂时只有一位标注者，
同一人应在完成第一轮并间隔一段时间后再做第二轮；第二轮开始前不显示第一轮答案。

报告必须给出：完全一致条数、存在分歧条数、无法判断条数，以及加权 Cohen's kappa。
Cohen's kappa（科恩卡帕系数）用于扣除“碰巧选中同一等级”的一致性；加权版本让 0 与 2
的分歧比 1 与 2 更严重。范围通常是 -1 到 1，越接近 1 越一致，但本轮只有 30 条，结果
仍需结合具体分歧逐条解释，不能只看一个数字。

所有分歧必须先由人工裁决并冻结最终参考标签，之后才能运行模型。否则根据模型答案修改
人工标签会造成数据泄漏，使评测看起来更好但不能代表真实效果。

## 本地标注操作

先确认 PostgreSQL、Server（接收网页请求并读取媒体文件的 NestJS 服务端）和 Web 已启动，
然后打开：

`http://localhost:3000/evaluation/phase9a-c2`

操作顺序如下：

1. 第一位标注者选择轮次 A；如果只有一位标注者，则把 A 理解为第一次判断。
2. 播放场景时保持静音，只根据画面逐项选择“是 / 否 / 不确定”。页面会自动推导整体等级，
   并在每完成一条后写入浏览器 localStorage。本地存储只存在当前浏览器中，刷新页面可以
   继续，但清理浏览器站点数据会删除它。
3. 完成 30 条后点击“导出轮次 A 标注”，保留下载的 JSON 文件。
4. 第二位标注者在看不到 A 文件的情况下选择轮次 B。若由同一人复标，应间隔一段时间，
   且第二轮开始前不要打开 A 文件。
5. 完成 B 后导出 JSON。把两个文件交给一致性检查工具；它会重新计算每条自动等级，任何
   手工篡改或漏项都会报错。

导出两个文件后，可从仓库根目录运行：

```bash
PYTHONPATH=apps/worker-py .venv/bin/python \
  -m media_agent_worker.phase9a_c2_annotation_agreement \
  --packet apps/web/data/phase9a-c2-blind-packet.json \
  --annotation-a /你的下载目录/phase9a-c2-annotation-A.json \
  --annotation-b /你的下载目录/phase9a-c2-annotation-B.json \
  --output /tmp/phase9a-c2-agreement.json
```

该命令只读三个本地 JSON 文件，并把一致条数、分歧样本 ID、无法判断数和加权 kappa 写入
新报告；数据库写入和云端调用均为 0。

盲标包指纹为
`sha256:c016eb5a2a06500fe5e38eeb16cd9930601f89581f37836c1c2ec339406f1afc`。
指纹是对全部题目、UUID 和时间边界计算的摘要；任意内容变化都会得到不同值，因此 A/B
文件不会被误配到另一批样本。

## 后续模型测试（本次代码提交不执行）

冻结参考标签后，可在重新取得明确外发授权的前提下，对 Qwen3-VL-Plus 和
Qwen3-VL-Flash 各运行 3 次。30 条 × 2 个模型 × 3 次 = 180 次调用。费用先按最坏上限
预留；根据上一轮真实用量推算约 0.41 元，但供应商控制台账单才是最终事实。

本轮主要报告新 30 条的等级准确率、三次稳定率、逐约束错误和理由—等级一致性。准确率是
模型最终等级与冻结人工等级完全相同的样本数除以可判断样本数，0% 到 100%，越高越好；
稳定率是同一题三次输出相同等级的题数占比，越高只说明重复一致，不保证答案正确。
